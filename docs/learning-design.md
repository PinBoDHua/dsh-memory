## 0. 目标与边界

把「手动记忆库 + 全量平铺注入」升级为「**信号触发 → 分级把关 → 可撤销 → 能纠错 → 库变大仍读得准**」的闭环。

“零重复、不复犯、默认生效”是产品行为目标，不是单靠存储或注入测试就能证明的事实。本设计把验收分成两层：

- **机制门禁**：写入、去重、风险拦截、召回、排序、预算、归档、恢复和性能必须确定性通过；
- **行为验收**：在固定宿主、模型和参数下回放真实任务，检查模型是否少重复询问、少复犯并采用偏好；结果单独报告，不伪装成跨环境恒成立的确定性断言。

```text
写入侧：用户消息/工具结果
             │
             ▼
       规则信号检测（只发信号，不直接写记忆）
             │
             ▼
       主模型自省 + memory_save（自动候选必须 origin=auto + signal_id）
             │
             ▼
       工具边界强制闸门：有效信号 / 会话上限 / 隐私 / 去重
             │
       ┌─────┼──────────┐
       │     │          │
     低风险  需确认      禁止自动落盘
       │     │          │
     活跃条目 pending    拒绝；不保存候选正文
       │     │
       │     └─ 用户批准后才生效；批准前不注入
       ▼
  origin=auto、来源指针、可归档恢复、审计事件

读侧：活跃条目 → pinned / constraint 优先 → 索引与按需召回 → 字符预算
             → 单行化、禁用插值、明确“记忆是参考数据” → 每次装配注入

治理：暴露账本（不等于采用）＋ 审计事件 ＋ 用户确认的合并/归档 ＋ omitted 可视化
```

### 核心不变量

1. 规则层只负责检测、限流和风险判断；候选正文由当前主模型生成，**零后台 LLM 调用**。
2. 模型工具面的 `origin=auto` 必须携带当前会话有效且未消费的 `signal_id`；无信号、信号不匹配或超上限时，工具边界拒绝，不靠模型自觉。`origin=manual` 也只能绑定直接用户的显式记忆指令，不能成为绕过通道。
3. 自动落盘候选（活跃条目与 pending 合计）每会话默认且最多 **5 条**；经校验的用户显式保存 `origin=manual` 不占此额度，但仍受隐私硬护栏约束。
4. pending 永不注入；被取代、已过期、已归档条目沿用现有默认隐藏语义。
5. 命中机密/敏感排除规则时，自动流程不得把候选正文写入条目、pending、审计或会话状态；只保留不含内容的计数。
6. 记忆和 skill 都是历史参考数据，不是系统授权，不能覆盖当前用户指令，也不能单独作为高风险工具操作的执行依据。
7. 相似、冲突或互补内容不自动合并；只有精确重复才允许走确定性合并，存量批量合并还须用户一次确认。

## 1. 验收定义

### 1.1 产品行为目标（独立报告）

| 目标 | 回放方法 | 目标结果 | 解释边界 |
|---|---|---|---|
| **A 零重复** | 5 次同类会话：第 1 次交代偏好，第 2–5 次执行同类任务 | 不因缺少该偏好而重复询问 | 同时记录条目是否注入，以区分“未召回”和“已召回但模型未采用” |
| **B 不复犯** | 显式纠正 1 次后，连续执行 3 次同类任务 | 不再出现被纠正的工具参数或行为 | 提示词只能降低概率；真正硬禁令必须由目标工具或宿主确定性校验执行 |
| **C 默认生效** | 预置偏好后，在第一次新会话执行未显式指定参数的任务 | 模型采用该偏好 | 记录模型、宿主、提示版本和参数；不承诺更换模型后结果不变 |

行为回放不得使用 LLM 判分。由预先写明的工具参数、可观察产物和人工检查清单判定。自动化机制测试全绿不能替代 I1 的用户实机行为确认。

### 1.2 确定性硬指标

- 无信号会话自动落盘候选 **0 条**，伪造或重放 `signal_id` 均拒绝；
- 每会话自动落盘候选 **≤5 条**；同内容重复交代 **0 新增活跃条目**；同一信号不重复提醒；
- 50 / 200 / 500 三档库中，排序、预算裁剪和 `omitted` 精确匹配预期；
- 在“pinned + constraint 总长度不超过预算”的 fixtures 中，注入率 **100%**；预算为 0 或内容超预算时按既定规则省略并显式计数，不作不可能的 100% 承诺；
- 归档后恢复，目标条目正文与 frontmatter **逐字节一致**；审计和访问账本允许追加 operational 变化；
- 500 条固定 fixture 在交付机器上预热后执行 200 次纯选择＋渲染，**P95 ≤20ms**；另报含磁盘读取的端到端装配耗时，不把两者混为一谈；
- 每个增量抽 **3 条**真实会话人工复核，记录结果但不作为跨环境自动化硬门禁。

## 2. 已确定的设计决策

| # | 决策 | 选择 | 约束 |
|---|---|---|---|
| 1 | 学习对象 | 用户偏好、项目/世界事实、程序性知识 | 不做无约束“自我改进” |
| 2 | 信任模型 | 低风险自动生效；可审阅候选进 pending；禁止项拒绝 | 自动写入一律 `origin=auto`、可撤销 |
| 3 | 主动性 | 静默复盘、系统侧冲突提醒、确定性周期摘要、面板分区 | 不要求助手在会话开始主动向用户播报 |
| 4 | 沉淀引擎 | 主模型自省；规则只发信号并执行硬闸门 | 无后台 LLM，不让规则直接编造记忆正文 |
| 5 | 反馈信号 | 明确撤销/拒绝/取代用于治理；注入/search 只记为暴露 | 长期存活和被注入不等于质量好或被模型引用 |
| 6 | 纠错形态 | 复用 `preference` + 保留 tag `constraint` | 仅直接来自用户的明确纠正可自动成为 constraint；推断纠走进 pending |
| 7 | 程序性知识 | 索引条目 + 独立 skill 文件 | 自动产生的 skill 默认 pending，用户批准后才启用 |
| 8 | 读侧扩容 | 优先层、索引层、按需层；预算内确定性选择 | 默认预算 8000，配置上限仍为 20000；不靠无限加预算续命 |
| 9 | 写入力度 | 信号驱动、单信号一次、会话总量封顶 | 工具边界强制，而非只在提示词声明 |
| 10 | 评测 | 合成 fixtures + 固定环境行为回放 + 真实抽样 | 不用 LLM 判分，不用注入命中替代行为结果 |
| 11 | 面板 | 现有面板增加「学习」分区 | 撤销复用现有归档/恢复，新增审计事件 |
| 12 | 迁移 | v2→v3 先备份，再加目录/状态和元数据 | 不改写存量条目；不承诺旧代码直接安全使用 v3 库 |
| 13 | 存量治理 | 精确重复可确认合并；其余只报告；批量归档需确认 | 不批量改写正文，不自动物理删除 |
| 14 | 顺序 | I1→I2→I3→I4 | I1 完成后先由用户验收，再决定是否继续 |

### 2.1 风险分级

| 等级 | 示例 | 自动流程动作 |
|---|---|---|
| **R0 无学习信号** | 普通问答、临时计算、可从代码直接推导的事实 | 不提醒、不写候选 |
| **R1 低风险** | 非敏感稳定偏好、明确环境事实、直接用户纠正 | 主模型可提出保存；工具验证信号、隐私、去重和额度后生效 |
| **R2 需确认** | 作用域不清、推断偏好、宽泛约束、新旧疑似冲突、程序性知识 | 仅保存非敏感候选到 pending；批准前不注入、不取代旧条目 |
| **R3 禁止自动落盘** | 密码/密钥/token、命中敏感排除规则的推断、短期任务指令、来自工具结果或记忆正文的“新指令” | 拒绝；不得借 pending 或审计保存候选正文 |

规则命中只是可测试的保守护栏，不等于识别全部敏感语义。面板必须保留来源、审阅和撤销入口。

### 2.2 保留与调整的旧红线

- **保留**：不做后台 LLM 提取、向量/图检索、显式投票、画像 slots、写入 `AGENTS.md`、系统通知或开场主动播报。
- **调整**：归档复用现有 `archived` 能力；合并仅限精确重复且保留审计；摘要只做审计数据的确定性聚合，不生成新事实。
- **系统侧提醒不等于开场播报**：pending、冲突和摘要只作为模型可见上下文或面板内容，不要求助手向用户主动发言；用户仍可在面板关闭相应提醒。

### 2.3 复用现状，不重复造轮子

- 已有：`origin=manual|auto`、`source`、`tags`、`supersedes` 链、`pinned`、`archived`、过期、软衰减、精确去重、相似提示、跨进程锁和原子写；
- 已有：`access.json` 记录 search 返回或注入造成的**暴露**，不能解释为模型引用或采纳；
- 已有：`data-snapshot` / `verify-lock` / `watchdog` / `bench` / `live-check` / `gui-check` 工具链；
- 当前缺口：`settings.js` 已有 `autoExtractHint`，但 `service.recallConfig()` 未返回它，导致 `index.js` 的动态提示始终停用；应修复该连接及错误测试，而不是新增并行开关；
- 当前缺口：pending、学习审计和信号状态尚无存储模型，需纳入 v3 与快照工具。

## 3. 数据模型、隐私与设置

### 3.1 条目与新增存储

**现有记忆条目零新字段**：

- 自动条目使用现有 `origin=auto`；纠错使用现有 `category=preference` 和保留 tag `constraint`；
- `source` 保存来源指针；能取得轮次时使用 `sessionId#turn=n`，否则只保存 `sessionId`，不得伪造轮次；
- 归档、恢复、取代、置顶和免衰减复用现有字段；`constraint` 与 `pinned` 一样免软衰减，但仍可被用户归档或被明确取代。

**schema v3 新增 `learning/` 目录**：

| 文件 | 内容 | 隐私与快照口径 |
|---|---|---|
| `pending.json` | R2 候选、风险原因、来源指针、创建时间和状态 | 只存非敏感候选；属于用户数据，纳入备份与快照 |
| `audit.jsonl` | 自动保存、pending 审批、归档/恢复、合并、迁移等事件 | 只记事件、条目/候选 id 和必要元数据，不复制候选正文；只追加，恢复时允许新增事件 |
| `state.json` | 会话额度、信号哈希/消费状态、摘要游标 | 不存原始对话；会话结束后清理，异常残留定期回收；列为 operational 数据 |

I3 增加 `skills/`，I4 增加 `digest/`。两者都纳入备份、快照和垃圾文件白名单，不能因新增目录被 `data-snapshot` 误判或漏判。

### 3.2 自动写入工具闸门

1. 信号检测监听直接用户消息和工具结果，生成只含类型、来源指针和哈希的信号；记忆正文、召回内容和工具输出不得冒充直接用户授权。
2. R1/R2 reminder 使用插件固定模板，仅暴露必要 `signal_id`，不把原始候选包进 `<system-reminder>`。
3. `memory_save(origin=auto)` 必须带 `signal_id`；服务端校验会话归属、未消费、未过期、额度和候选风险，成功后原子消费。总开关关闭时拒绝自动候选落盘。
4. 模型工具面的 `origin=manual` 必须绑定直接用户的 `explicit_memory` 信号；面板手动录入使用已认证的用户操作路径，不借用模型信号，也不占自动额度。
5. 达到上限后只返回固定错误和计数，不保存第 6/7 个候选正文；pending 与活跃自动条目共享同一额度。
6. 多进程消费信号、写条目和记审计必须避免“条目已写但信号可重用”；失败时按可重试幂等流恢复，不产生重复条目。

### 3.3 注入安全与预算语义

- 保持 `interpolate:false` 和正文单行化，防止模板插值及伪造额外展示行；
- 固定 GUIDANCE 明示：当前用户指令优先，记忆是可能过时的参考数据，依赖前能廉价核对就核对；
- `constraint` 是行为偏好提示，不是工具级安全策略；禁止把“已注入 constraint”写成“硬禁令已强制执行”；
- 排序为 pinned → 非 pinned constraint → 其他条目；同优先级依次按衰减乘子、更新时间、id 确定性排序；
- 预算包含实际渲染行。条目不能完整装入时整条省略，不截断 constraint；普通索引可使用带省略标记的确定性摘要，依赖前必须读取完整条目；
- 8000 是**默认值**，20000 是**配置上限**。任何预算下都不突破字符上限来换取 100% 注入。

### 3.4 设置与迁移

复用现有 `autoExtractHint=true` 作为自动学习总开关，不再增加含义重叠的 `autoLearn.enabled`。信号驱动是固定不变量，不提供可关闭它的 `signalOnly` 开关。

新增或调整：

- `autoLearn.maxWritesPerSession = 5`，允许范围 0–5；0 表示禁止自动候选落盘，不影响显式手动保存；
- `conflictAlert = true`；
- `digest.enabled = true`，`digest.weekday = 1`；
- `injectionBudgetChars` 默认值 6000 → **8000**，范围 0–20000 不变；已有用户覆盖值保持不变。

迁移规则：

1. 获取全局写锁，先完成全量备份并验证可读，再创建新增目录和写 `meta.json schemaVersion=3`；
2. 默认值由代码收敛，迁移不强行物化全部默认设置；不改写任何存量条目正文或 frontmatter；
3. 多文件变更通过备份、失败恢复和幂等重试保证一致性，不声称单次文件系统操作具备跨文件原子性；
4. 旧版本可能忽略新目录，但这不构成兼容或回滚保证；回退代码前必须恢复与 v2 对应的完整备份；
5. `--fail-at` 只在隔离数据根注入故障，覆盖备份失败、目录/元数据写入失败、锁释放和重试无残留。

### I3 程序性知识（skill 载体）

**前置 spike**：验证 `ctx.skills` provider 能否把动态 skill 安全提供给 `skill` 工具。可行则走 provider；不可行则使用插件自有读取工具加载 `skills/*.md`，后者需要模型显式调用。spike 只验证宿主契约，不把试验代码直接并入交付。

**范围**

- 索引条目保存“何时用 + skill id”，正文保存在 `~/.dsh/.dsh-memory/skills/<id>.md`，不写全局 skills 目录；
- skill 带版本、修订和来源；自动产生的 skill 先进入 pending，用户批准后才可被索引和加载；
- skill 与记忆一样属于不可信参考数据；加载工具校验 id 和路径，拒绝路径穿越及未批准内容；
- 归档、恢复、备份、快照和回滚复用 I1/I2 基础能力。

**文件边界**：新 `lib/skills.js`、`index.js`、`lib/{store,service,render,routes}.js`、`client/client.js`、`tests/*`、文档与版本文件。

### I4 冲突提醒、确定性摘要与面板完善

**范围**

- 规则只生成“疑似冲突候选”，进 pending 并保留双方来源；不得宣称完整理解语义，不自动覆盖旧条目；
- pending/冲突提醒仅在有变化时写入系统侧上下文，内容只含数量和面板入口，不重复播报候选正文；
- 周报是对审计事件的确定性聚合：自动写入数、批准/拒绝、撤销、冲突和归档数量及条目链接，不调用 LLM、不生成新事实；
- 默认在每周一之后的首次会话装配一次；无事件不注入，游标防止重复，宿主不常驻时无需调度器；
- 完善面板批量审批、撤销审计和摘要存档；真实会话回放按 §1 单独报告。

**文件边界**：新 `lib/digest.js`、`index.js`、`lib/{service,routes}.js`、`client/client.js`、`tests/*`、`scripts/{gui-check,eval-replay,data-snapshot}.mjs`、文档与版本文件。

### 每个增量的完成定义（DoD）

- TDD：先失败测试后最小改动；新增回归测试进入 `node --test tests/*.test.mjs`；
- 三段验证：unit 全绿 + `live-check` 全绿；涉及面板时 `gui-check` 全绿；既有测试以当前总数为准，不冻结 204 等历史数字；
- 破坏性、迁移和故障注入用例使用隔离数据根；真实数据根快照不得出现白名单外变化，白名单必须逐项列出；
- `data-snapshot` 覆盖新增的 pending、audit、skills 和 digest；恢复验收区分“条目字节一致”与“审计/访问账本允许追加”；
- 按上表做 minor 版本号、CHANGELOG 和文档同步；重装插件后立即运行 live-check；
- 每个增量保持单一可回滚提交；提交和推送按当次用户授权执行，本设计文档的确认不等于提交或推送授权；
- I1 交付后暂停，由用户完成行为目标实机验收，再决定是否进入 I2。

## 6. 风险与回滚

| 风险 | 概率 | 缓解与剩余风险 |
|---|---|---|
| 模型忽略 reminder 或误解信号 | 中 | 工具闸门、来源指针、行为回放和撤销；机制正确不保证模型行为永远正确 |
| 记忆投毒 / 提示注入 | 中 | 直接用户来源约束、单行化、禁插值、参考数据声明、pending 审批；不能把提示防护当作高风险操作的替代品 |
| 敏感内容误写 | 中 | R3 硬拒绝、pending 同样过滤、审计不存正文、真实抽样；规则存在漏检可能 |
| 过度记录或绕过额度 | 中 | signal 一次性消费、活跃＋pending 共享上限、manual 语义校验、超限不保存正文 |
| 注入膨胀或关键条目溢出 | 中 | 预算硬上限、优先排序、omitted 原因和面板预览；不承诺无限条目全部常驻 |
| 错误合并 / 归档 | 中 | 精确重复边界、用户确认、保留历史、审计与恢复；相似内容不自动处理 |
| 迁移或回滚失败 | 低 | 全局锁、备份验证、故障注入、幂等重试；v3 库不直接交给旧代码回退 |
| 性能门槛受机器影响 | 中 | 固定 fixture、预热、P95、记录硬件与 Node 版本，分别报告纯函数和端到端结果 |
| `ctx.skills` provider 不可用 | 中 | I3 前置 spike；降级为受控读取工具，不修改 DSH 核心 |
| 冲突检测误报/漏报 | 高 | 只称“疑似冲突”，必须人工确认，不自动取代；接受规则无法完整理解语义 |
| 周报重复或打扰 | 低 | 无事件不注入、游标去重、系统侧呈现、可关闭，不要求助手主动播报 |

**回滚原则**：代码用对应增量的 `git revert`，数据用该增量前的匹配备份恢复；先恢复数据再运行旧代码。归档/恢复的日常撤销不删除审计，迁移回滚则以完整备份快照为准。

## 7. 实施边界

- 本稿确认只表示设计文本可作为实施依据，**不等于授权立即修改代码**；开工仍需用户明确下达 I1 实施指令；
- 实施严格按 I1→I2→I3→I4，每个增量独立验收；I1 未完成实机行为验收前，不默认继续后续增量；
- 默认预算 8000、默认开启自动学习和确定性周报均纳入 I1/I4 的实机验收，发现打扰或 token 成本不可接受时先调整，不静默扩大范围；
- 不重开已经排除的宿主核心改造、后台 LLM、向量检索或全局 skill 写入；确需新增能力时先回到设计评审。

## 8. 不做清单（Non-goals）

- 后台 LLM 提取、会话结束后自动跑 LLM 或 dreaming 式全自主学习；
- 向量/图检索、embedding；
- 显式投票/打分 UI；
- 画像 slots、bi-temporal 时间戳、git 版本化记忆；
- 写入 workspace 的 `AGENTS.md` 或全局 skills 目录；
- 保存原始对话作为学习状态，或在 pending/审计中夹带 R3 候选正文；
- 把记忆、constraint 或 skill 当作高风险工具操作的确定性安全护栏；
- 自动合并相似、冲突或元数据不同的条目；
- 会话开始要求助手主动播报「我记得…」；
- 任何形式的物理删除（除用户显式 `forget`）；
- 系统通知/弹窗（宿主无 API）。
